# LumiDex v0.8 — 屬性交換效益分析（開發預覽）

日期：2026-11-08。分支：`dev/v0.8-tradeoff`，**未發布正式版**。

## 使用情境

使用者在指定怪物／地圖掛卡、打怪時，想知道減少物理或魔法穿透、改成 ATK%／MATK%、爆擊傷害、主屬性 DEX，單次攻擊效果是否會改善。純穿透升幅計算不足以完成這個判斷。這個階段保留原 `analyzer.html` v0.6，新增獨立 `tradeoff.html` 與純函式 `tradeoff-model.js`。

### 操作與輸入

- 從卡片首頁「設定與工具 → 屬性交換效益試算」或 v0.6 分析器入口開啟，選擇地圖和單一怪物；不選怪物時逐隻列出一般怪物（可另選 Leader），**絕不輸出無權重地圖平均值**。
- 選物理/魔法傷害、是否能暴擊、是否必中。比較 A（目前）與 B（更換後）的穿透百分點、ATK%／MATK% 總加成、實際適用的爆擊率、額外爆傷百分比。
- 進階：A/B HIT、DEX。DEX 變動時，必須填寫角色原本面板 ATK/MATK，以及 **每增加 1 DEX 造成的面板攻擊變化**；未填時只顯示已知子項，不顯示總收益或 B 的傷害門檻。
- 可在選擇單隻怪物後，輸入 A 配置在該怪物身上「命中且非爆擊」的實測單次傷害，顯示 B 的條件式非爆擊傷害與全部命中且未暴擊時的理論擊殺次數。未輸入則不虛構實際傷害值。
- A/B 的角色最終面板、技能可否爆擊與 ATK% 仍需**手動校準**，任何預設數字只是示範。v0.8.1 新增選用的 Explorer 裝備資料匯入（如下），僅自動讀取公開裝備詞條，**不**代表能讀取最終角色面板、不保存個人配裝。

## 已公開核對的模型

官方來源：<https://www.lumivaraonline.com/wiki/>（Combat & Stats，2026-11-08 查閱），怪物快照沿用 `monster-stats.json`。

1. `armor = 1 - max(0, min(DEF,255)/300 - pierce/100)`；物理只看 DEF，魔法只看 MDEF。暴擊**不**略過護甲。
2. `chance = clamp(1 + (HIT-FLEE)*0.0025, 0.4, 1)`；僅勾選已確認必中才取 1。
3. 官方描述暴擊為 **原始傷害 ×2，另外加上暴擊傷害百分比**。假定該技能可暴擊時，使用使用者提供的爆擊率 `c` 和額外爆傷 `d`：平均命中傷害比重 `1 + c * (1+d)`，其中 `c,d` 都以 0–1 表示。法術暴擊率不同於物理面板，應依法術爆擊條件輸入，不自動從物理 CRIT 推定。
4. A→B 的條件式期望傷害倍率：`armorRatio × attackRatio × criticalExpectationRatio × hitChanceRatio`。期望值是單次嘗試的機率加權平均，不是確定一擊傷害、實際施放速度、DPS 或經驗收益。

## 未證實而明列的近似

- 當 ATK%／MATK% 變動時，試算暫以「所有相關百分比加成在同一乘區內加總」的條件模型 `(1+B總加成/100)/(1+A總加成/100)`。**官方未提供足夠可驗證的完整堆疊公式；此結果一律標為條件式，必須用遊戲面板或實測確認。**
- DEX 的 ATK/MATK 影響沒有跨職業通用換算公式，且依職業、武器、被動與技能而變。只有在使用者提供「每 +1 DEX 對面板 ATK/MATK 的實測變化」後，才近似 `(原面板攻擊 + ΔDEX × 係數)/原面板攻擊`，且仍未納入 DEX 影響的 HIT/詠唱/攻速/技能門檻；HIT 必須另填。
- 若使用者將 ATK% 與 DEX 同時變動，兩個近似倍率相乘，並**不**保證包含加成之間的交互項。將來應優先允許直接填 A/B 實測面板攻擊做高信度替換。

## 不包括的能力／風險

- 不包括技能倍率、真正的職業傷害來源（如 The King STR=INT 混合、特殊必中與特殊增傷）、屬性克制、元素附魔、武器類型、怪物抗性、攻速、SP、場上怪物密度、刷新與移動時間，因而**沒有可靠的實際掛機效率、DPS、EXP/h 或配裝排行**。
- 爆擊率資料使用者需輸入「目前技能適用」的值；某些技能不能爆擊，需要取消勾選。不能把期望傷害換算為保證擊殺次數。
- v0.8.1 導入**裝備本身詞條差異**，並非卡片完整裝配模擬；尚不計算附卡、精煉、職業被動或角色面板的隱藏加成。不更動 88 卡／90 怪／18 地圖／72 材料索引及收藏 key。

## v0.8.1 — Explorer 公開裝備匯入（Dev，非正式功能）

### 使用方式

1. 在 `tradeoff.html` 展開「從官方 Explorer 匯入角色裝備」，輸入角色**名稱**（不是數值 ID），按「開啟 Explorer 並讀取」。
2. 第一次在裝置上使用時，先安裝儲存庫中的 `explorer-bridge.user.js` 到 Chrome 可支援的 Userscript 擴充功能，或 iPhone Safari 的 Userscripts 擴充功能。腳本僅匹配 `lumivaraonline.com/explorer/*`，且只在網址帶有 `lumidex=1` 時啟動，不需要遊戲帳密。
3. 腳本在**官方同網域**讀取公開 `/api/explorer/player?name=...`；透過先前 `window.open` 建立的頁面間 `postMessage` 傳回已刪減的裝備資料。LumiDex 只接受該已開啟視窗、來自官方 Explorer 網域、角色名稱相符的訊息；Userscript 只回覆白名單開發/正式來源。
4. 若 Safari 分頁隔離或腳本未正常傳回，可在官方頁面按「複製匯入資料（備援）」；返回比較器「沒有自動連線？改用複製貼上」貼入 JSON，過程仍由瀏覽器本地運算。
5. 匯入後選一件「目前穿戴」（`gear[].worn===true`），搜尋背包或倉庫中**相同裝備部位**的候選裝備，立即查看各詞條增減。相同 `accessory1` 的兩枚戒指按照裝備序號分別選取，不合併。
6. 「以 A 為基準，將已知差異套用 B」只帶入穿透（對應當前物理／魔法類型）、爆擊傷害、DEX、HIT。其餘 B 欄位會先重設成 A，不把舊示例數字當成換裝效果。ATK 固定值**不是 ATK%**、CRIT 點數**不是實際爆擊機率**、卡片及精煉不是已驗證直接換算；僅展示詞條差異。A 的角色實際面板、DEX 換算與技能效果仍需人工輸入，不能將這一階段結果當作傷害保證。

### 架構與隱私邊界

- 官方 API 已實測**不提供**讓 `github.io` 直接讀取的 CORS header，因此只用靜態 GitHub Pages 的 fetch 會失敗。本階段不建立公共代理伺服器、不引入密鑰、不把資料複製成正式站靜態檔案。
- `explorer-bridge.user.js` 僅處理使用者主動開啟的公開玩家頁，轉送 `name`、`level`、`classId`、`gear` 與 `storage.gear`，不轉送 Silver、Gold、其他背包物品、交易／充值紀錄。使用者手動貼完整官方 JSON 時，`explorer-import.js` 仍只保留必要欄位。
- 不使用 localStorage、Cookie、Session、公開 GitHub、遠端計量服務保存或收集使用者角色裝備；資料只在當前瀏覽器頁面記憶體，重整後消失。相容收藏原有的 `lumidex-v1-favs`，不操作它。
- 安全檢查：按角色名稱匹配、裝備欄位型別／數值界限、同部位相容、XSS 安全 DOM 的 `textContent` 顯示、跨分頁來源與 `event.source` 比對，不插入官方伺服器資料或頁面外掛。
- 只用公開資料，不讀取遊戲記憶體、不繞過登入或遊戲私人資料。官方可能改版或取消 API，應提供失敗訊息與手動備援。
- 實測瀏覽器公開測試角色資料：10 件穿戴、832 件背包／倉庫候選；Chrome 本地跨分頁 bridge handshake、備援貼上與套用、320–428px 手機寬無橫向溢出。**iPhone Safari Userscript 實機尚未驗證**。
