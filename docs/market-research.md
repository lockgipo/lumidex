# 卡片市場價格研究

2026-11-08 · LumiDex v0.4.0 的本機試驗

## 資料來源

- 目標是每張卡在同一市場區域的最低有效 Silver 掛賣單價。用圖鑑的卡片 ID 對應紀錄，頻道可供排查，市場分區依官方 FAQ。
- [官方 Explorer](https://lumivaraonline.com/explorer/) 的市場頁面提供稀有物品、拍賣及 Gold 交易。Silver 交易和流向屬於帳本資料，無法回答普通卡片現在有哪些掛單。公開 Wiki 可核對卡片，沒有提供掛單。[官方卡片索引](https://lumivaraonline.com/wiki/cards/)
- V108 市場畫面有卡片類別、「選擇卡片」精確篩選與價格由低到高。可人工核對每張卡的第一筆掛賣單價，再將結果整理成一批。前次 SEA 觀察從 777 筆掛單變成 787 筆，每頁 9 筆，價格也會在觀察期間變動。同卡可有多筆掛單，熱門搜尋和總列表前幾頁無法判定其餘卡片有無掛單。
- 交接提到的遊戲內多卡查詢有 50 筆限制。低價卡的重複掛單會擠掉高價卡，因此即使能查到回應，也無法據此判定涵蓋 88 張。尚未確認官方提供可授權使用的全量查詢、匯出或排程頻率。自動採集須先取得官方允許的管道及使用範圍。[官方使用條款第 5、11 節](https://lumivaraonline.com/legal/)
- [官方 FAQ](https://lumivaraonline.com/faq/) 說明遊戲內市場依區域分開。現階段只整理最低掛賣價，實際成交、裝備市場、材料收益分開處理。

- 實測先取得第 2 頁 9 筆（817 總掛單），切換第 1 頁後自動追加另外 9 筆（818 總掛單）。同日還觀察到 787 筆到 817/818 筆的變動，並出現提燈妖怪卡片 4,399 → 4,000 Silver 的不同時點價格。**僅代表畫面當下可見掛單**，不代表完整市場最低價普查。
- 未確認當次市場區域，所以腳本標示 `region: unverified`。觀察紀錄仍是掛單層級的 `cardName` / `askSilver`，不是 88 張卡片的完整最低價快照；不能把沒看見的卡片記成無掛單，更不能當成成交均價或直接匯入正式圖鑑價格。
- 官方條款第 5 節禁止外部程式代玩家控制遊戲，因此此腳本**沒有自動翻頁、批次搜尋、遊戲網路請求或排程**。如果未來官方提供允許的資料出口，才評估無人操作的全量定期更新。

## 在本機保存人工批次

1. 在遊戲內選定區域，使用卡片分類、精確卡片篩選與價格由低到高。只記錄第一筆有效 Silver 掛賣的單價。確認該卡沒有掛單才填 `null`，還沒查、載入失敗或結果不確定就省略該卡。
2. 用實際觀察的起訖時間填寫下列 UTF-8 JSON。卡片 ID 可在 [data.json](../data.json) 依 `nameZh` 查找。每區每批每張卡只填一次。目前接受整數 Silver，與 v0.4 手動輸入相同。以下數字與時間為格式示例。
3. 將輸入與歷史資料留在儲存庫以外。輸出資料夾使用 Windows 本機 NTFS。工具會印出有價、確認無掛單和未查核數量，並按區域與結束時間保存；相同內容可重跑，同一區域及結束時間的相異內容會回報衝突。

```json
{
  "version": 1,
  "source": "manual",
  "currency": "Silver",
  "region": "SEA",
  "startedAt": "2026-11-08T01:00:00Z",
  "finishedAt": "2026-11-08T01:05:00Z",
  "cards": [
    { "cardId": "card-sand-drake", "lowestAsk": 12345 },
    { "cardId": "card-dune-gecko", "lowestAsk": null }
  ]
}
```

時間用 UTC。範例的 `01:00Z` 相當於台灣時間 09:00。區域接受 SEA、East Asia、EU、NA、AU。

```powershell
node scripts/record-market-snapshot.cjs "$env:LOCALAPPDATA\LumiDex\market-input.json" "$env:LOCALAPPDATA\LumiDex\market-history"
node --test
```

## 在圖鑑中查詢批次價格

在頁面上方選擇與批次相同的市場區域，展開「匯入卡片行情」，再選取保存後的 JSON。匯入結果會顯示批次涵蓋張數。可用卡片名稱搜尋、依最低掛賣價排序，並在卡片詳情查看觀察時間。

每張卡以批次結束時間標記觀察時間。同時間或較新的價格會保留，未查核的卡片和已有的 7 日成交均價不受匯入影響。已確認無掛單的卡片會顯示「當時無掛單」。匯入結果保存在目前瀏覽器，歷史以本機 JSON 檔為準。

## 接上全量來源後的驗收

1. 先以 SEA 核對卡片 ID、區域、賣方掛單、Silver 單價與時間。若來源提供的是掛單列表，必須完整分頁或使用可保證每張卡最低價的查詢。以人工精確搜尋交叉核對高價、低價、大量重複掛單及零掛單的案例。
2. 一批只有在 88 張各自確認有最低價或無掛單後才算查齊。逾時、分頁截斷與未知 ID 都應列為未確認，歷史中的舊價仍須顯示原時間。確認官方允許的頻率後再安排定期採集。
3. 先做同區域的最新觀測排序和逐卡時間序列，顯示資料時間、覆蓋率、缺口。掛賣價可用來看價格，成交量才可衡量交易熱度。
4. 掛機價值用已驗證掉落率、每小時實測擊殺量和近期掛賣價估算，並按來源及角色效率分組。樣本不足的卡保持未知。若需算淨收益，再納入上架費、成交稅及成交機會。
